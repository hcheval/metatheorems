# WHyperbolicDSL.lean

## module header

### Two theories, and what each checks

**`WHypDSL`** (first half) lets the command generate its own `κ` and `F`, as a theory declared
from nothing would.  Its formulas therefore live over a *different signature* from
`WHyperbolic.lean`'s (`WHypDSL.κ` is an inductive with one constructor `W`; the hand-written
file uses `κ = Unit`), so `Formula WHypDSL.F Γ` and `Formula WHyperbolic.F Γ` are different
types and no equation between them is well-formed.  What is checked instead is that the
command produces **exactly the de Bruijn spelling a person would have written**: `expW1` …
`expW4` are `WHyperbolic.ax_W1` … `ax_W4` transcribed character for character, with only
`WHyperbolic.d ↦ (Term.dist ())` and `WHyperbolic.W ↦ WHypDSL.W` changed — every `Var.vs`
chain intact — and each `example` closes `WHypDSL.ax_Wᵢ = expWᵢ` by `rfl`.  The
non-degeneracy of those four `rfl`s was checked by breaking one index; see the comment there.

**`WHypSig`** (second half) uses the `signature` clause to take `WHyperbolic.κ` and
`WHyperbolic.F` instead of generating them.  Then the comparison is direct:
`WHypSig.ax_Wᵢ = WHyperbolic.ax_Wᵢ` and `WHypSig.Premises = WHyperbolic.Premises` all by
`rfl`, derivations pass between the two without transport, `WHyperbolicModel.axiomsHold`
inhabits the *generated* `Obligations` structure with no re-proof, and
`WHyperbolicModel.w_metatheorem` comes back out of the generated `WHypSig.metatheorem`
applied to a model.  So for this space the DSL can **replace** `WHyperbolic.lean` lines
62–208 rather than parallel them.

What is still hand-written in `WHyperbolic.lean` and is not generated by anything here: the
model (`WHyperbolicModel`), its interpretation `si`, `W1_holds` … `W4_holds`, `WMajorant` and
`W_maj`, `abstractMajorizability`, `constMajorants`.  That is the mathematics, and the
command asks for it rather than supplying it.

## the check `example`s (docstring)

**Non-degeneracy, checked and not assumed.** Swapping the two `X` arguments of
the second `W` in `expW3` — i.e. writing `(.var (.vs (.vs .vz))) (.var (.vs .vz))` where
(W3) has `(.var (.vs .vz)) (.var (.vs (.vs .vz)))`, which is *exactly* the mistake a person
counting `.vs`es makes — turns the third line below into a `Type mismatch` at
`WHyperbolicDSL.lean:171:46` and nothing else in the file changes.  So these four `rfl`s do
discriminate the index assignment; they are not four instances of `rfl : x = x`.

## The `signature` clause (section doc)

That is the answer to the header's caveat: the obstacle was the generated signature, not the
generated formulas, and one clause removes it.
